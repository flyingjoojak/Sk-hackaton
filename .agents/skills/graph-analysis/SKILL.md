# graph-analysis

판정과 합계는 코드가 한다. 그래프 DB 와 학습 모델은 6시간 기본 범위가 아니다. 저장은 CSV 와 `dict`. networkx 가 있으면 차수 중심성 대조에만 쓴다.

자세한 표는 `~/sk-hackaton/docs/기업분석_알고리즘_대비.md`, 스키마는 `~/sk-hackaton/docs/거래관계_온톨로지.md`, 예측 문제는 `~/sk-hackaton/docs/예상문제.md`(공식 아님). 참고 구현은 `python3 ~/sk-hackaton/tools/graph_ref.py`. 과제 폴더에 통째로 복사하지 말고 필요한 함수만 다시 짠다.

## 1. 계약에서 고르기
- 과제 문장과 가장 가까운 계산 하나만 필수로 둔다. 나머지 유형은 개선이거나 안 함.
- 담당자에게 `docs/기업분석_알고리즘_대비.md` 3절을 숫자로 묻는다. 답이 없는 기준(비중, 깊이, 금액/물량)은 `(확인 필요)`.
- 방향: supplier → buyer. 손실 금액은 끊긴 직접 간선만. 간접 금액을 더하지 않는다.

## 2. 순서
1. `python3 ~/sk-hackaton/tools/peek.py` 로 열, 빈 값, 금액 범위를 본다.
2. 기준선: 직접 거래 표(누가 누구에게 얼마). 이것만으로 첫 완주가 될 수 있다.
3. 그다음 하나만: HHI, 단일 공급(비중 >= 기준, 같으면 포함), BFS 전파(깊이 상한), 대체처(같은 자재, 금액 내림차순, id 동률).
4. 조건 변경(부도, 국가, 단가 상한)은 JSON 으로 받고 간선 복사본에서 제거한 뒤 다시 계산한다. 원본은 그대로 둔다. 출력은 추가·삭제 diff.
5. 문장 → JSON 은 `templates/agent/reanalyze.py` 의 규칙이 먼저. LLM 은 `$llm-feature` 대로, 키가 없으면 규칙만.

## 3. 검사
- 생성 함수와 다른 루프로 HHI, 단일 공급 집합, (기업, 깊이)를 다시 센다.
- 틀린 HHI 를 넣으면 검사기가 잡는지 테스트를 한 번 실패시켜 본다.
- 손계산 표본: 80 대 20 의 HHI 는 0.68. 합이 0이면 비중을 만들지 않는다.
- 제외 행은 건수와 금액 합을 전후로 보고한다.

## 4. 시간
150분까지는 2번에서 고른 하나와 검사기 테스트. 240분에 기능 추가를 멈춘다. 화면은 그 다음, 표 하나.
