# 기업 간 거래·기업정보 분석 대비

예측 주제다. 공식 문제가 아니다. 당일 과제가 같거나 비슷하면 이 순서를 쓰고, 다르면 구조만 가져간다. 구조는 기준선 > 개선 > 독립 검사기, 그리고 6시간 컷이다.

참고 구현: `python3 ~/sk-hackaton/tools/graph_ref.py` (표준 라이브러리, 자체 검사). 과제 코드에 그대로 복사하지 말고 필요한 함수만 다시 짠다. 예측 문제 10개는 `docs/예상문제.md`.

## 1. 문제를 한 문장으로

구매자와 공급자의 거래로 그래프를 만들고, 한 기업이 멈추거나 비중이 한곳에 몰릴 때 어느 자재가 위험한지 표로 보여 준다. 최적 발주량을 풀지 않는다.

## 2. 질문 유형과 알고리즘

| 유형 | 6시간 알고리즘 | 기준선 | 검사 |
|---|---|---|---|
| 공급망 리스크 전파 | 중단 기업에서 구매자 방향 BFS. 깊이 상한. 손실은 직접 간선 금액만 | 직접 거래(깊이 1)만 | 집합과 깊이를 다른 루프로 재계산 |
| 단일·과점 공급처 | 구매자·자재별 비중 >= 기준. 같으면 포함 | 공급처가 정확히 1곳 | 원본 금액 합으로 비중 재계산 |
| 집중도 HHI | Σ (비중^2), 0~1 | 1위 비중만 정렬 | 50:50 → 0.5, 80:20 → 0.68 |
| 중심성·브릿지 | 차수 중심성 (in, out) / (n-1) | 거래 건수 정렬 | networkx 가 있으면 차수만 대조. 없으면 생략 |
| 대체 공급처 | 같은 자재를 파는 다른 기업, 금액 합 내림차순, id 로 동률 해소 | 후보 나열만 | 중단 기업과 자기 자신은 없어야 함 |
| 2·3차 의존 | 위 BFS 의 max_depth 2 또는 3 | 깊이 1 | 순환에서 재방문 없음. 깊이 상한과 같으면 포함 |
| 기업 유사도 | 자재 집합 Jaccard. 시간 남을 때만 | 같은 자재 하나라도 겹치면 후보 | 완전 일치 1, 공집합 0 |
| 이상 거래 | 직전 기간 대비 금액 또는 단가 증가율 >= 기준 | 절대 금액 상위 | qty 0, 직전 0 은 비율 대신 확인 필요 |
| 이름 통합 | 공백·회사 표기 제거 후 완전 일치. 애매하면 후보만 | id 기준, 이름 무시 | 병합 전후 금액 총합 동일 |
| 재무 경보 | 표 규칙 (적자, 자본, 매출). `$data-judge` | 영업이익 < 0 만 | 빈 칸을 0으로 채우지 않음 |
| 조건 변경 재분석 | 문장 → 허용된 JSON → 간선 제거 → 위 지표 재계산 → 집합 diff | JSON 을 손으로 넣음 | 같은 조건은 같은 diff. 원본 불변 |

버린 것: 최소비용 흐름, 정수계획, GNN, PageRank, betweenness 전수(기업 수백이면 시간). betweenness 는 "차수로 부족하다"는 담당자 답이 있고 노드가 적을 때만.

## 3. 담당자에게 물을 것

숫자와 업무 장면으로 묻는다. `docs/담당자_인터뷰.md` 순서를 먼저 하고, 이어서:

- 결과는 누가 보고 어떤 결정(대체 발주, 협상, 보고)을 하나?
- 공급 방향은 "우리 회사 기준 구매"인가, 다기업 네트워크인가? 우리 회사 id 는?
- 집중도와 전파는 금액인가 물량인가? 기간은 한 행이 이미 합산된 값인가?
- 단일 공급의 기준 비중. 그 값과 같으면 포함하는가?
- 부도 시 깊이 몇 차까지 보는가. 2차 공급자가 일부만 끊겨도 1차가 완전히 멈춘다고 볼 것인가, 직접 금액만 볼 것인가?
- 국가 코드 표기(KR, 대한민국)는 이미 정리되어 있는가?
- 이름이 비슷한 협력사를 자동으로 합쳐도 되는가, 후보만 내면 되는가?
- 놓치는 경보와 잘못된 경보 중 어느 쪽이 더 곤란한가?
- 단가 상한은 어느 열과 비교하나? 같으면 제외인가 유지인가?

답이 없는 숫자는 `(확인 필요)` 로 두고 코드 상수에 적지 않는다. 제출을 위해 가정하면 TASK.md 가정 칸에 "틀리면 무엇이 깨지나"를 쓴다.

## 4. 데이터 검증 (계산 전에)

- 필수 열, 중복 거래 키, 빈 id, companies 에 없는 id(있으면 간선은 유지하고 이름만 `확인 필요`)
- amount 음수·0, qty 0, 자기 거래, period 형식
- 제외 건수와 제외 전후 금액 합. 입력 행 수 = 사용 + 제외 + 오류

## 5. 기준선과 개선 (`graph_ref.py` 순서)

1. CSV 를 읽어 간선 리스트를 만든다. 같은 키는 금액을 합친다.
2. 기준선 = 직접 거래 표(누가 누구에게 얼마). 그래프 지표 없이 이것만으로도 담당자가 대조할 수 있다.
3. 구매자·자재별 비중과 HHI.
4. 비중 >= 기준인 단일·과점 공급.
5. 중단 기업 BFS. 기본 깊이는 과제 문장. 없으면 3이고, 그 선택은 DECISIONS.md 에 적는다.
6. 같은 자재의 다른 공급자를 금액 순으로 제안.
7. 조건이 바뀌면 간선 리스트를 복사해 제거한 뒤 3~6을 다시 하고, 기업 id 와 자재의 추가·삭제만 출력한다.

차수 중심성은 개선이다. "이 회사가 브릿지다"라고 말하려면 차수와 함께, 그 회사를 뺐을 때 새로 끊기는 구매자가 있는지를 전파로 보여 준다. 중심성 숫자만 단독 근거로 쓰지 않는다.

## 6. 독립 검사기

생성 함수의 반환값을 믿지 않고 원본 간선으로 다시 센다.

- HHI 를 금액에서 다시 계산해 1e-9 이내로 같은가
- 단일 공급 집합이 같은가
- 전파의 (기업, 깊이) 가 같은가. 깊이는 부모를 따라 다시 센다
- 대체처에 제외 기업이 없는가
- 일부러 틀린 HHI 를 넣으면 오류 목록이 비어 있지 않은가

실패를 한 번도 못 본 검사기는 제출 전에 틀린 입력을 한 번 넣는다.

## 7. 모듈과 상태

```
CSV 로드 > 검증(제외 건수, 금액 합) > 간선 리스트(불변 원본 + 합산본)
  > 비중/HHI > 단일 공급 > 전파 > 대체처
  > 조건 적용(복사본) > 재계산 > diff
  > 표 또는 화면은 저장된 결과만 읽음
```

원본 간선, 현재 조건, 마지막 결과 셋은 각자 하나의 객체다. 재분석이 원본을 지우면 서술형에서 깨진다.

## 8. 엣지 케이스

금액 합 0 / 비중 기준과 같음 / 기준 바로 아래 / 공급처 하나 / 순환 / 깊이 상한과 같은 노드 / 없는 company_id / 자기 거래 / 금액 0 / 국가 빈 값 / 같은 조건 두 번(결과가 같아야 함).

## 9. 서술형에 쓸 문장 (숫자와 파일명은 당일 것으로 바꾼다)

사실 > 결정 > 근거 > 한계.

1. "직행에 해당하는 기준선은 직접 거래 표였습니다. 담당자가 끊기는 하위 기업까지 보자고 해서 BFS 로 깊이를 제한해 전파했습니다. 손실 금액은 직접 간선만 더했습니다. 간접 금액을 곱하면 이중 계산이라 버렸습니다. 순환이 있으면 깊이가 과대입니다. 고치려면 표본에서 재방문이 0인지 검사기로 봅니다."
2. "HHI 는 비중 제곱합이고 80 대 20 표본이 0.68 이었습니다. 1위 비중만 보여주는 안은 나머지가 얼마나 쪼개졌는지 숨겨서 버렸습니다. 금액이 0인 행은 비중을 만들지 않습니다."
3. "구현한 것은 로드, HHI, 전파, 검사기입니다(테스트 N개). 가정은 깊이 상한과 금액 기준입니다. 평가자는 `python3 -m pytest -q` 와 검사기 오류 0으로 확인합니다."
4. "조건 문장은 규칙으로 JSON 에 넣었습니다. LLM 출력은 type 허용 목록으로 검사하고, 키가 없으면 규칙을 씁니다. 그래프 숫자는 LLM 에 맡기지 않았습니다."
